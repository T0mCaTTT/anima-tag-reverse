# 功能说明 · 英文自然语言分支与缺项补全（上一轮改造）

> **第 6 期起 CLI 的默认输出是「混合形态」**（第一行质量/分级行、按层各一行标签、空行后一句英文自然语言、再空行负向词）。本文写成时默认还是「单行标签串」，所以正文里凡是「默认单行标签串 / 默认 tags 不动」都是**当轮口径**（要旧形态现在得显式 `--format tags`）；混合形态、`--loose`、`--theme`、提醒三件套的现行为见 `SKILL.md` 的「## 输出契约」「## 第 6 期」两节。
> 后续一轮（B+C 改造）又动了三处，本文档的描述按当时状态保留，最新行为以 `SKILL.md` / `README.md` 为准：
> 1. **两个入口都默认带缺项自审、都默认不宽召回**（`reverseImageSpec` / `reverseText` 空 opts 都带 `{gaps:true}`，要宽召回得显式 `{broad:true}`；CLI 两个入口都默认开自审，`--image-spec` 额外打 stderr 摘要，文本入口不打）；
> 2. **观察 JSON 的 `notes` 降级为纯日志**（不再产分句；只有「整份输入没有任何结构化键」与 `JSON.parse` 失败时才整段当文本）；
> 3. **缺口从五类变六类**（新增 `C-spec-*` kind `missingObservation`：必填观察维度没落成结构化字段，计入 `gapsSummary.specMissing`）；另外 `--format gaps` / md / stderr 里的建议写法不再被条数上限截掉。
> 4. 之后一轮（A2 修复）恢复了被误压的变体压制：文本入口的「变胖标签」（如 `微笑` 出 4 条 smile 变体）不再出现，图像样张窄召回因此 34 条 → 33 条（少掉 notes 硬凑的 `sideways mouth`）。
> 另外本文正文不再引用历史自测数字（用例数会随轮次变化，抄进来就会过期）；当前为 `node tests/smoke.mjs` 36 例 + `node tests/spec-audit.probe.mjs` 120 例（后者含 2026-10-07 16:35 归档真值的严格等值断言）。

上一轮在 `skills/anima-tag-reverse` 上做了两件事：加一条**英文自然语言**输出分支，和一套**缺项自审 + 候选勾选**的补全回路。原有的标签反推链路顺带修了四处召回缺口。

默认行为完全没变：不传 `--broad` / `--nl` / `--gaps` 时，输出与改造前逐字节一致（当时自测里有一条用例专门锁这件事，现在由 `tests/spec-audit.probe.mjs` 的等值基线继续锁）。

## 一、新增能力一览

| 能力 | CLI | 会话内（API） | 产物 |
| --- | --- | --- | --- |
| 英文自然语言 | `--nl` / `--format nl` | `reverseText(text, { nl: true })` → `out.nl` | `{ text, sentences, tagLine, negative, rating, meta, markdown }` |
| 缺项清单 | `--gaps` / `--format gaps` | `reverseText(text, { gaps: true, alternatives: true })` → `out.gaps` / `out.gapsSummary` / `out.gapsMarkdown` | 结构化 `gaps[]` + markdown 勾选表 |
| 一次给全 | `--check` / `--format check` | 同上两个开关一起 | 标签串 + 负向串 + 自然语言 + 缺项清单 |
| 宽召回 | `--broad` | `{ broad: true }` | 阈值放宽 + 备选池扩大（**同时影响标签行**：样张 33 条 → 41 条；也影响 `--nl` / `--gaps` 的候选丰富度） |

`--gaps` / `--check` / `--nl` 三个开关会**接管输出形态**（等价于 `--format gaps` / `check` / `nl`）；但如果同时显式写了 `--format tags`，它们就只当附加产物开关，默认单行标签串照常输出。

## 二、关键实现

### 1. `src/hints.mjs`（新增，13,003 字节）——规则补充层

词库是 Danbooru 标签库，中文覆盖靠 `EXTRA_ZH` 手工补，长复合词和口语人数天然会漏。这层用纯查表补上，不改词库：

- `COUNT_GROUPS`：口语人数与性别 → 真实标签（`两个人` → `2girls`、`一男一女` → `1girl` + `1boy`、`一个人` → `1girl` + `solo`…）。
- `GENDER_WORDS`：性别词表（女孩/少女/女生…）。
- `CJK_DECOMPOSE`：中文复合词拆解，`colors` / `patterns` / `garments` 三组。`蓝白条纹水手服` → 尾词 `水手服`(`sailor dress`) + `蓝白`(`blue`) + `条纹`(`striped`)。
- `SHORT_ALIASES`：常见中文短说法直接给英文标签（`逆光`→`backlighting`、`过膝袜`→`thighhighs`…）。
- `ruleSurfaces()` 按长度降序排列，保证最长优先。

### 2. `src/parse.mjs`——接入规则层

`parseCounts()` 按四步收口：整串命中 → 按性别累计 → 数字与日文写法 → 冲突消解（同性别取最大值；有 `solo` 时不出现多人标签）。`decomposeCjk()` 切出尾词与修饰成分，产出 `{ kind:'garment' | 'modifier', zh, en, parts }`——**每一项都必须带 `parts` 数组**，漏了会在 `parse.mjs` 里抛 `TypeError: d.parts is not iterable`。

`parseClause()` 的 `forced` 顺序：引号 → `@画师` → `by 画师：X` → 人数 → `SHORT_ALIASES` → 复合词拆分。调试开关 `RTAG_NO_RULES=1` 可整体跳过规则注入，用来判断问题是出在规则层还是词库层。

#### 人数是文档级信息（本轮修掉的一类错读数）

分句各算一次人数会算出矛盾的结果，所以 `parseText()` 在分句解析之后统一重算：把每个分句里的人数标签全部滤掉（`COUNT_TAGS` 全集判定），用整段文本的紧凑串跑一次 `parseCounts()`，结果 `unshift` 回第一个分句。

`parseCounts()` 内部还有三条口径，缺一条就会读错：

1. **带性别的写法压过裸量词**。表里既有 `两个女孩`（性别明确）也有 `两个`（默认 girls）。裸量词的性别只是猜测，一旦句子里另有带性别的写法（`seeded`），后续裸量词直接跳过；同时记下 `bareCount` 与 `specificGenders`，把裸量词贡献的标签从结果里摘掉。判据按**键**（`GENDER_WORD_RE.test(h.k)`）而不是按标签——`两个` 和 `两个女孩` 映射的是同一组标签，按标签反推区分不出来。
2. **标签性别判定必须写成 `boy?s?` / `girl?s?`**。标签是单数 `1boy`，只写 `boys` 会让它落空，`1boy` 被当成裸量词摘掉。
3. **`1girl + 1boy` 谁也不能代表总人数**。`两个女孩，一个男孩` 的 `1boy` 只说了有个男的，女的人数（2）得从没被点到的裸量词 `2girls` 里取：两边都在时按 `女 = 裸量词数 - 1` 补一条确切读法。

`两个男生一个女生`、`三男两女` 这类紧写由 `COMBINE_RE`（带量词）与 `BI_GENDER_RE`（`三男两女` 不带量词）分担；紧写只在表里没有整串组合条目时生效，否则 `一男两女`（表里已有 → `1boy + 2girls`）会被拆成 `1boy + 1girl`。

排查期临时打开的 `RTAG_COUNT_DEBUG=1`（打印表命中、性别集合与收口结果）已随修复收掉：人数口径现在有回归用例兜着（`tests/smoke.mjs` 的「分句写的人数」「人数紧写」两组），不需要长期开关。

### 3. `src/match.mjs`——B2 规则词条 + 六道压制 + 备选池

- **B2 规则词条**放在表面扫描之后，分数固定 0.9（低于任何真实表面命中的 0.93–0.97）。三道跳过：同标签键已有更高分表面命中、拆出的中文核心已在候选里、被更长标签整词包含。用意是让「白色连衣裙的银发女孩」里规则拆出的 `dress` 不顶掉词库真实命中的 `white dress`，也不把 `silver hair` 挤出候选表。
- **中文核分组** winner 改为取 `freqN` 最大者（不是分数最高者）：`坐` 组里 `sitting`(1,300,000) 胜出、`sitting on`(0 投稿) 落选。这是「坐在椅子上看书」能给出 `sitting` 的原因。
- **频次先验**：`freqScore()` 对 `freqN = 0` 的标签返回 `SCORE.medianFs = 0.42`（全库归一化频次中位数）。这类标签有 4,599 条，含 `silver hair`、`girl`、`sitting on`；按 0 算等于把正常标签判成最冷门直接淘汰。
- **重叠表面消解**：`scanSurfaces()` 给命中打 `canon`（用户写的串就是该条目本名），重叠时「更长优先、同长优先 canon」。
- **备选池**（`opts.alternatives`）：够分但被名额挤掉的候选按层归拢，`BROAD.altPerLayer = 12` / `BROAD.altTotal = 80`，供缺项清单当候选项。

### 4. `src/nl.mjs`（新增，30,835 字节）——英文自然语言分支

Anima 官方模型卡写明标签串与自然语言可以混排：标签适合点名角色/作品/画师/构图，自然语言适合描述关系、方位、动作。所以这里不做逐词翻译，而是**按句子角色重排**。

句子骨架（与用户确认的「混合式」一致）：

```
[标签前缀一行]
One girl.
The character has <发色发型>, <瞳色>, <表情>
She is wearing <服装>, <配饰>, <鞋袜>
She is <姿势>, <动作>
The scene is set <地点>, <时间>, <光线>
The image is rendered <画风>, <媒介>, <画质>
```

三条自我约束：**确定性**（只查表 + 拼接，无随机，模型想润色就在这份骨架上改）、**不丢信息**（每个用上的标签记进 `meta.used`，走原样兜底的记进 `meta.fallback`，句末附标签串供核对）、**分级照写**（评分/分级只影响措辞强度，不做过滤）。

措辞三层：专属 `PHRASE` 表 → `inferPhrase()`（中文名词核 → 词尾形态 → 服装 → 修饰关键词 → 介词短语 → 动作）→ 原样兜底。

两个路由护栏（都是实测踩出来的）：

- `APPEARANCE_FORM_RE`：`hair|eyes?|skin|ears?|tail|wings?|horn|halo|blush|…` 的标签一律留外观句——词库把 `silver hair` 挂在 `og:image-composition`/层 7，光看层号会写成 "The scene is set … silver hair"。
- `SCENE_KEEP_RE`：场景/画风句只收带场景介词的措辞（`among|at|in|on|under|with|backlit|…`），过不了闸门的退回外观句。
- 动作拨层：`POSE_PHRASE_RE` 或 `SCENE_ACTION_RE` 命中的层 6/7 标签改归姿势句，否则 `reading` 会写成 "The scene is set … reading"。

### 5. `src/gaps.mjs`——缺项检测

五类缺口，每条带 `id` / `severity` / `why` / 候选项：

| 前缀 | 类型 | 判定 |
| --- | --- | --- |
| `A*` | 未匹配片段 | `res.unmatched` 非空 |
| `B*` | 关键层为空 | 层 1 / 4 / 6 / 7 无标签（层 4 为 `high`） |
| `C*` | 粒度不足 | 14 个维度（发色/发型/眼睛/表情/上衣/腿袜/景别/时间/光线/手势与持物/配饰/鞋/身体姿势/画风与媒介）一个取值都没给 |
| `D*` | 多主体信息不全 | 总人数 >1，但外观项不够每人 2 项 |
| `E*` | 同维度冲突 | `EXCLUSIVE` 13 对互斥（`day×night`、`long hair×short hair`、`standing×sitting`…；`1girl×1boy` 在总人数 >1 时不报） |

`C*` 的 14 个维度分组（`layer` 是候选标签所属层，`test` 决定「已有值就不再问」）：

| id | 名称 | layer | 判定命中（已有值） | 候选（`suggest` / `expect`） |
| --- | --- | --- | --- | --- |
| `hair-color` | 发色 | 4 | `xxx hair` 且非长发/短发类 | `black hair` / `blonde hair` / `silver hair` … |
| `hair-style` | 发型 | 4 | twintails / ponytail / braid / bangs / ahoge … | `long hair` / `short hair` / `twintails` / `blunt bangs` |
| `eyes` | 眼睛 | 4 | `xxx eyes` | `blue eyes` / `red eyes` / `green eyes` … |
| `expression` | 表情 | 4 | `PHRASE` 表命中且含 smile / cry / mouth 等 | `smile` / `open mouth` / `closed mouth` |
| `outfit-top` | 上衣 | 6 | shirt / dress / uniform / kimono … | `shirt` / `school uniform` / `sailor dress` |
| `legwear` | 腿袜 | 6 | thighhighs / kneehighs / pantyhose / garter belt | `thighhighs` / `black thighhighs` / `kneehighs` / `pantyhose` |
| `framing` | 景别 | 7 | full body / upper body / cowboy shot / close-up / portrait … | `upper body` / `full body` / `cowboy shot` / `close-up` |
| `time` | 时间 | 7 | day / night / sunset / morning … | `day` / `night` / `sunset` |
| `lighting` | 光线 | 7 | lighting / backlight / shadow / glow … | `backlighting` / `soft lighting` / `rim light` |
| `hand-gesture` | 手势与持物 | 6 | `holding *` / `hand on own *` / `hand to *` / crossed arms / waving … | `holding book` / `holding cup` / `holding umbrella` / `hand on own chest` / `crossed arms` |
| `accessories` | 配饰 | 6 | hair ornament / hair ribbon / necklace / earrings / ring / glasses / hat … | `hair ornament` / `hair ribbon` / `necklace` / `earrings` |
| `footwear` | 鞋 | 6 | boots / loafers / sneakers / mary janes / high heels / sandals / barefoot | `boots` / `loafers` / `sneakers` / `barefoot` |
| `pose` | 身体姿势 | 6 | standing / sitting / lying / on back / kneeling / walking … | `standing` / `sitting` / `kneeling` / `walking` |
| `art-style` | 画风与媒介 | 7 | anime screenshot / official art / monochrome / sketch / chibi / 3d … | `anime screenshot` / `official art` / `sketch` / `monochrome` |

写 `test` 时必须用文件顶部的 `anyOf()` / `endsWith()` 助手生成正则，别写裸正则：`keyOf` 把空格换成 `_`，`close-up` 这类连字符也会存成 `close_up`，写成 `/full body/` 会永远匹配不上。`close-up` 的 key 是 `close_up`、`hand up` 的词库条目名是 `hand_up`、`hand to mouth` 存的是 `hand_to_mouth`——三处都踩过。

这 5 个新维度的候选全部经词库实查（层号、投稿量都核过）：配饰类在词库里统一叫 `hair ornament`（2.1M / `og:accessories`）、`hair ribbon`（803.8k）、`earrings`（867.9k），并没有 `hand ornament` 这种条目；`standing` / `sitting` 各 1.3M（`og:posture`）；`official art` 549.1k 与 `anime screenshot` 15.7k 同挂 `og:image-composition`；`sneakers` 97.9k、`loafers` 85.9k 挂在 `og:attire` 的「鞋类」子类下。

候选项统一 `{ id, label, zh, tag, score?, source, why }`，`source` 四值：`alt`（宽召回备选池）/ `preset`（固定建议）/ `manual`（词库没有，需用户自己给英文标签）/ `choice`（二选一）。

粒度维度从 9 组扩到 14 组，补的是**词库本来就覆盖、只是此前没被问出来**的维度（这是「候选更全」的实际瓶颈，不是召回阈值）：

### 6. `bin/rtag.mjs`——接线

新增 `--broad` / `--no-broad` / `--gaps` / `--check` / `--nl` / `--with-tags` / `--no-tags` / `--max-per-sentence N` / `--nl-template`；`--format` 增加 `nl` / `gaps` / `check`；`--format json` 附带 `gaps` / `gapsSummary` / `naturalLanguage`；默认报告末尾追加缺项段落。

**本轮修掉的一个接线 bug**：`--gaps` / `--check` / `--nl` 起初只置布尔开关、不改 `opt.format`，而输出分支判的是 `opt.format`，于是 `--gaps` 和 `--check` 静默返回默认标签串（`--nl` 也一样）。现在这三条会接管 `opt.format`，但用户显式写了 `--format` 时让位。

## 四、自审清单

### 4.1 多选补全回路（我执行时逐项过）

- [ ] 原描述先跑一次 `--broad --check`，拿全量缺口与候选
- [ ] `A*` 未匹配片段：能补词的补进 `EXTRA_ZH` / `SHORT_ALIASES`，补不了的直接问用户换说法
- [ ] `B*` 关键层为空：每层至少给出 3 个候选（`alt` 优先于 `preset`，同层同维度不重复）
- [ ] `C*` 粒度不足：只问「大类写了但没给取值」的维度，不问已给的
- [ ] `D*` 多主体：逐人问，别把所有人的外观混成一句
- [ ] `E*` 冲突：二选一（`choice`），不做自动取舍
- [ ] 候选项列给用户时**编号 + 中英对照 + 一句为什么**，让用户只回勾选号
- [ ] 用户勾完 → 追加进原描述 → 重跑 `--check` → 缺口归零才算收尾
- [ ] 用户明确跳过的缺口记下来，不再重复问
- [ ] 分级内容照写不降级（用户已确认）

### 4.2 终审字段核对表

| 检查项 | 期望 |
| --- | --- |
| `bare` 单行 | 无换行、逗号 + 空格分隔、首尾无逗号 |
| 前缀 | `bare` 里不得出现 `masterpiece` / `best quality`；`score_*` 是唯一带下划线的标签 |
| 分级 | 内容含 `cb:nsfw` 时至少抬到 `nsfw`；`--rating` 显式指定时按 `min(3, 前缀长度)` 插位 |
| 负向 | 每个否定分句最多 2 条、总分上限 8、`score < 0.6 && !forced` 丢弃 |
| 自然语言确定性 | 同一输入连跑两次逐字一致 |
| 自然语言信息完整 | `meta.used` 覆盖性：用到的标签数 + 兜底数 = 进入句子的标签数 |
| 自然语言兜底 | `meta.fallback` 里的标签逐条看措辞是否可接受，不行就补 `PHRASE` |
| 缺项不误报 | 描述完整的输入不得报 `conflict`（回归用例已锁） |
| 层号 | `res.layers[].tags[]` 每条都要有 `layer`，否则自然语言全落 `other` |
| 默认零破坏 | 不传三个开关时输出与改造前逐字节一致 |

## 六、已知缺口与后续可选动作

- 词库没有 `schoolgirl` / `high_school_girl` 这类通用「女高中生」标签（只有各校具体校服），所以「女高中生」兜到 `girl`；要精确只能动词库。
- 中文长复合词（如「蓝白条纹水手服」）靠 `CJK_DECOMPOSE` 查表，未登记的复合词仍会漏；这是查表法的上限，真要泛化得引入分词或词向量。
- `BROAD` 档的阈值（`0.38 / 0.44 / perClause 6`）是实测挑的，没有大规模标注集验证；候选质量主要靠 `score` 排序，缺项清单不保证候选一定贴切。
- 自然语言的措辞表 `PHRASE` 是人工维护的，新标签出现怪措辞时表现为句子可读性下降（不会丢标签，`meta.fallback` 会记下来）。
- `gaps.mjs` 的 `EXCLUSIVE` 只有 13 对，覆盖的是最高频冲突；长尾冲突（如 `rainy` × `sunny` 之外的组合）还没进表。
