# Anima3 提示词组装（anima3-prompt-builder）

把「中文场景描述」按 **ANIMA3 模板 v3.1** 组装成一条英文 prompt。模板全文归档在
`references/anima3-template-v3.1.md`（2214 行），本文件是**可操作的执行版**：
什么时候查哪一节、输出什么形状、交付前跑什么检查。

## 与原 anima-tag-reverse 的分工

| | anima3-prompt-builder（本技能） | anima-tag-reverse |
|---|---|---|
| 方向 | **正向**：中文描述 → prompt | **反向**：图片/描述 → 标签串 |
| 依据 | ANIMA3 v3.1 模板（规则 + 实战标签库） | 本地 38,306 条词库检索 |
| 开头 | **必带质量词 + `@画师名`** | 默认不带前缀（可加） |
| 光效词 | **禁止**（lora 已内置） | 允许，且会自动补 |
| 强项 | 槽位顺序、体位/特殊主题配方、互斥自检 | 查词、反推、分级适配 |

**两者可以串起来用**：本技能出 prompt → 用 `bin/lookup.mjs` 借 reverse 的词库体检标签。

## 输出契约（硬要求）

| 要求 | 做法 |
|---|---|
| 行数 | **仅 1 行**，无换行、无 markdown、无 code fence、无引导语 |
| 分隔 | `, `（逗号 + 空格） |
| 大小写 | 全 lowercase；`score_*` 保留下划线；`@画师名` 保原样 |
| 权重 | **禁止**写 `(tag:1.2)`——字段顺序即隐式权重 |
| 开头 | 质量词 3-6 个 → **紧跟** `@画师名` |
| 禁止 | 光线/光影/色调标签（`sunlight`/`rim light`/`warm lighting`/`bloom`…，lora 已内置） |
| 允许 | 环境天气描写（`rain`/`snow`/`fog`/`steam`） |
| 标签数 | 单人 20-36 / 双人 26-44 / 复杂 34-54（含质量词与画师） |
| 自然语言 | 标签说不清的（角色归属、复杂构图、剧情）→ 英文短句，**统一放末尾** |

**槽位顺序**（靠前权重更高）：

```
[quality] → [artist] → [count/gender] → [character/series] → [appearance]
→ [clothing/state] → [pose/action/sex] → [expression/reaction] → [camera/shot]
→ [scene/environment] → [detail/mood] → [英文自然语言补充]
```

**开头模板**：`masterpiece, best quality, highres, score_9, @eonsang, ...`

## 工作流

1. **匹配场景类型**（查 `references/anima3-template-v3.1.md` §5 决策树）
   - 5.1 单人展示 · 5.2 双人前戏 · 5.3 双人正戏 · 5.4 特殊体位（睡奸/催眠/攻守反转/过激）
   - 5.5 多人/群交 · 5.6 百合 · 5.7 特殊主题（NTR/束缚/RBQ/男娘Futa/异种/调教/胁迫/偷窥/事后/另类日常/大车小孩/隐奸）
   - **5.7 类必须先查 §14 对应章节**拿跨槽位配方，再按最接近的 5.1-5.6 填槽位
2. **定质量词 + 画师**（§4.0 与 §6.0）
   - 质量词：基础必含 2-3（`masterpiece`/`best quality`/`highres`）+ 精修按需 + 评分 1-3（`score_9` 最强）
   - 画师：用户指定 → **原样输出**，不查库；未指定 → 按风格从 §6.0 画师库选 1 个（风格不明默认 `@eonsang`）
3. **逐槽填标签**（§6-§13 各槽位库）
   - 标签数控制见 §4.2；服装槽天然最多
   - 视线默认规则（§4.3）：**单人默认注入 `direct eye contact, facing viewer`**，除非用户要背影/侧脸
4. **多人场景**（§4.6）：每个角色**必须**补关键外观（`角色名 with 发色 + 瞳色 + 特征`），动作关系放末尾自然语言
5. **风格一致性**（§4.1）：古风配古风、赛博配赛博、日常配日常，不跨世界观硬拼
6. **自检**（§3 清单 + §3.1 互斥表）→ **跑校验器**（见下）
7. **输出**：单行纯文本，无任何包裹

## 自检：别靠脑子记，直接跑校验器

模板 §3 的自检清单已实现成脚本，17 条回归用例锁着：

```bash
cd <技能根目录>
node bin/check.mjs "masterpiece, best quality, highres, score_9, @eonsang, 1girl, solo, ..."
node bin/check.mjs --file prompt.txt        # 从文件读
node bin/check.mjs - < prompt.txt           # 从 stdin 读
node bin/check.mjs "..." --json             # 机器可读
```

覆盖的规则：

| 规则 | 来源 | 级别 |
|---|---|---|
| 单行 / 无 markdown / 无权重语法 | §2 | error |
| 质量词存在且在最前（3-6 个） | §3-0 / §4.0 | error |
| `@画师名` 存在且紧跟质量词 | §3-0b / §4.0 | error |
| 禁止光效/色调词（30+ 词表，**有四条白名单**） | §2 | error |
| 重复标签（**含权重写法穿透**） | §3-3 | error |
| 人数一致性（`solo` 配多人、`group sex` <3 人） | §3-1 | error |
| 互斥标签（视角/身份/服装/动作/细节过度，20+ 组） | §3.1 | error |
| 标签总数区间（按人数自动选档） | §4.2 | warning |
| 大小写 | §2 | warning |

### 光影白名单（用户放行的四条）

模板 §2 默认禁止一切光效/色调词，但用户拍板放行这四条：

| 标签 | 中文 | 放行原因 |
|---|---|---|
| `soft lighting` | 柔光 | 通用柔光，多数柔和插画需要 |
| `bloom` | 泛光 | 逆光泛光效果 |
| `bokeh` | 散景 | 背景虚化光斑 |
| `gradient sky` | 渐变天空 | 天空渐变（偏环境而非打光） |

**白名单是精确整词匹配**——不会连带放行同类词。
例如 `soft lighting` 放行，但 `hard lighting` / `studio lighting` 仍被拦截。

其余光效词（`sunlight`、`rim light`、`backlighting`、`lens flare`、`warm colors`、
`glowing`、`neon lights` 等）**照旧禁止**。

**退出码**：0 = 无 error；1 = 有 error。**交付前必须跑到 0**。

## 标签体检：借本地 38k 词库

模板里的标签来自实战统计，不保证都在本地词库。生成完可以逐条查库，标出拼写错误与冷门标签：

```bash
node bin/lookup.mjs "masterpiece, best quality, score_9, @eonsang, 1girl, solo, ..."
node bin/lookup.mjs "..." --missing-only     # 只看未收录
node bin/lookup.mjs "..." --json
```

输出分三档：**命中**（附中文释义 + 投稿量 + 层级）、**未收录**（可能拼错）、**冷门**（投稿量低，模型可能不熟）。

> ⚠️ 「未收录」≠「标签错误」——本词库 38,306 条，模板是另一套来源。仅作参考，不阻断。

## 模板自身的已知矛盾（实测发现，供判断）

校验器跑模板自带示例时抓到过矛盾，**这不是脚本的 bug，是模板原文不自洽**：

| 位置 | 矛盾 | 建议 |
|---|---|---|
| §15 示例（末条） | 正向里写了 `neon lights`，但 §2 明令禁止光效/色调标签 | 以 §2 为准，删掉；要霓虹氛围改用场景词（`nightclub`/`bar counter`） |
| §2 与 §13 | §2 禁「光线/色调」，§13 的「氛围基调」里又收了不少色调向词 | §2 优先级更高，色调词一律不进 prompt |

**遇到模板内互相打架时：§2 OUTPUT PROTOCOL 最高优先级**（它定义交付形状），其次 §3/§3.1，再次各标签库。

## 边界

- **不做**负向提示词（模板只管正向）。需要负向用 anima-tag-reverse。
- **不做**权重建议——模板明令禁止权重语法，靠槽位顺序表达优先级。
- 模板 §15 EXAMPLES 是占位（原文如此），案例需自行积累。
- 零依赖：只用 Node 内置模块；`lookup.mjs` 需同机装有 anima-tag-reverse（自动探测，可用 `ANIMA_REVERSE_SKILL` 指定）。
